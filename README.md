# Agentia Gov Guard

Pre-promotion policy checks, PROD approval gates and audit reports for Agentia CLI.

Built for the Agentia Headless Virtual Hackathon as an oclif plugin on top of the public `agentia` CLI. It only shells out to public commands and never imports private Agentia internals.

## Install

```sh
npm install
npm run build
agentia plugins link .
```

Re-run `npm run build` after every change to the TypeScript files.

## Commands

```sh
agentia gov check --story US-1234 --env UAT-SFP
agentia gov check --story US-1234 --env PROD
agentia gov check --story US-1234 --env PROD --approve-code AP-XXXXXX
agentia gov check --story US-1234 --env UAT-SFP --json
agentia gov approve AP-XXXXXX --story US-1234 --env PROD
```

`gov check` verifies authentication readiness via `agentia auth get --json`
(CICD set, CRT `ready:true`, AI set), warns when story context or
environment values are missing, and blocks PROD targets until a one time
approval code is presented. With `--self-heal` it prints the exact
`agentia ai agent ask` Operate diagnosis command for the failure instead of
guessing.

`gov approve` consumes a one time code generated by a prior PROD check and
records the approval for audit.

## Why it matters

The Agentia docs note there are no data specific rollback, retry, resume,
validation only or deployment status commands, destructive operations always
need confirmation, and large Profiles can break commits. Gov Guard puts a
repeatable policy gate in front of promotion so teams catch those risks early
and keep JSON evidence for review.
